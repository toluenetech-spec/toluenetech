## Source of Truth

**Neon Postgres** is the primary application data source. **R2** is the canonical object store. **Firebase** is being retired (see `docs/data-source-strategy.md` and `docs/migration-plan.md`) — during the transition, the public website still reads from Firebase/DataContext defaults (see audit) but all new endpoints, auth, media upload, AI, and admin CRUD target Neon.

## Database

- Driver: `@neondatabase/serverless` via Drizzle ORM (`drizzle-orm/neon-http`). Per-request drizzle instance.
- Migrations: `server/drizzle/` generated by `drizzle-kit generate`. Apply with `npm run db:migrate`.
- Schema: `server/src/db/schema.ts`. All tables use `crypto.randomUUID()` primary keys.
- Tables introduced in Phase 1: `audit_logs`, `ai_usage`. Additions: `clients.access_code`, `clients.last_login_at`, `clients.email UNIQUE`, `media.visibility/role/project_id/client_id`, `notifications.client_id`, `project_files.client_id/uploaded_by_role/visibility`, new enums `audit_action`, `file_visibility`.
- **Foreign keys are NOT applied yet.** Migration `0002_foreign_keys_manual.sql` is staged but requires running orphan-reporting queries first (see migration).

## Request Flow

1. **Global middleware** sets CORS, security headers, request ID, error handler.
2. **Router middleware** authenticates the request:
   - Public routes: no auth (rate limits where needed).
   - Admin routes: `authAdmin()` (accepts Bearer JWT signed by us, valid Firebase JWT matching `admin_users.uid`, or — in DEV_MODE only — the legacy password header).
   - Client routes: `authClient()` (accepts our Bearer JWT, valid Firebase JWT matching `clients.user_id`, or — DEV_MODE only — demo shortcut for bootstrap).
3. **Handler** parses JSON, validates with `lib/validate.ts`, authorizes resource ownership (`assertProjectOwnership`), performs DB operation, returns `{success,data}` on success or throws `ApiError` which is mapped to `{success:false,error:{code,message}}`.
4. **Audit** writes fire-and-forget to `audit_logs` for mutations.
